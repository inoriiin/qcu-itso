# QCU ITSO — project notes

## Stack
- Frontend: Vite + React 18 + TypeScript (`src/`)
- Backend: Supabase (Postgres + Auth + RLS) — schema in `supabase/schema.sql`
- Supabase client: `src/lib/supabase.ts` (env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` in `.env.local`)

## Commands (use `npm.cmd` on this machine — `npm.ps1` is blocked by execution policy)
- Dev server: `npm.cmd run dev` → http://localhost:5173
- Build/typecheck: `npm.cmd run build`

## Conventions
- Brand colors: `#002366` (primary blue), `#FD7201` (accent orange) — defined in `src/index.css` / `src/enhancements.css`
- Brand assets: `public/brand/qcu-logo.png` (QCU seal) + `public/brand/itso-logo.jpg` — referenced as `${import.meta.env.BASE_URL}brand/...` in TSX; favicon `/brand/qcu-logo.png` in index.html
- Dark theme: `src/dark.css` is GENERATED by `scripts/gen-dark.mjs` from index.css + enhancements.css — never hand-edit it. Edit the source CSS instead; regeneration runs automatically via `predev`/`prebuild` (`npm run gen:dark` manually). One-off dark tweaks go in a new `src/dark-manual.css` (import it in main.tsx after dark.css). Theme state: `data-theme` attr on `<html>`, localStorage `itso.theme`, inline init script in index.html (no flash), toggle in the avatar dropdown
- Colleges/programs per `QCU Structure.md` (5 colleges, 9 programs) — seeded in `supabase/schema.sql`
- Student ID format: `xx-xxxx` (year enrolled - unique number)
- Statuses/filing types are Postgres enums in `supabase/schema.sql` — keep `src/App.tsx` status/type lists in sync
- Live mode (signed in via Supabase) reads/writes Supabase via `src/lib/db.ts`; `localStorage` (`itso.*` keys) is only the offline fallback
- SQL run order (all already applied to the live project): `schema.sql` → `fixup.sql` → `phase3_notifications.sql` → `phase4_profiles.sql` → `phase5_scheduled_jobs.sql` (pg_cron) → `phase6_links_events.sql` → `phase7_email_cron.sql` (pg_net; secret placeholder must be filled in at run time, never committed) → `phase8_instant_email.sql` (instant send trigger + `claim_pending_notifications` RPC used by the Edge Function) → `phase9_self_profile.sql` (`update_my_profile` RPC for the "Update information" modal — **user must still run this one**; the app degrades gracefully if missing) → `phase10_coauthor_emails.sql` (author email column + `notify_submission` fan-out — **user must still run this one**) → `phase11_filing_deadlines.sql` (filing-date default, SER recompute, 60-day defects — **user must still run this one**)
- Status flow: `"Paper Submitted"` is DEPRECATED — enum value kept for history but new submissions start at `"Under Review"` (DB default + app lists exclude it). `default_filing_date()` sets `filing_date` when status hits `"Submitted to IPOPHIL"`; `trg_ser_on_filing` now fires on ANY submissions update and recomputes the SER problem + sends `ser_started` notifications whenever filing_date changes
- Formality defects: deadline = notice_date + **60 days** (exact); do NOT apply to Copyright (DB trigger rejects, UI hides controls); rounds display as `defectLabel(n)` = "1st/2nd/…/11th Formality Defect" in app + SQL + emails; `formality_defects.details` stores the admin's notice text. Reminders are stage-based (30d/7d/due, once each) and also go to owner + co-author emails
- Co-author notifications: `submission_authors.email` (optional, normalized+validated by trigger/constraint) — `notify_submission(submission, type, payload)` notifies the owner plus every distinct co-author email (payload gets `coauthor: true`); used by the status/remark/certificate/defect triggers. Co-author emails omit the workspace link (Edge Function branches on `p.coauthor`)
- New schema changes: add a new `supabase/phaseN_*.sql` file (idempotent: `if not exists`, `drop ... if exists`); user runs it in the Supabase SQL Editor, then `notify pgrst, 'reload schema';`
- Supabase gotchas: 403 / `42501 permission denied` = missing table GRANTs (this project doesn't auto-grant; see fixup.sql — covers `authenticated` + `service_role`), not RLS. `PGRST202` function not found = migration not run or schema cache stale.
- Mutations that RLS blocks with an UPDATE matching 0 rows return no error — keep that in mind when debugging "saved but nothing changed"

## Email / scheduled jobs
- `notifications_log` is both the in-app bell feed and the email outbox (`delivery_status`: pending / sent / failed_* / skipped). Rows are created only by DB triggers/jobs; recipient = student email or `'admin'` (expanded to all active admins at send time)
- Edge Function `supabase/functions/send-notifications/index.ts` is deployed via the Supabase dashboard editor (paste + Deploy; no CLI). Verify JWT is OFF; auth is the `x-cron-secret` header
- Delivery is instant: a statement-level trigger on `notifications_log` runs the `itso-email-dispatch` cron command via pg_net. Rows are claimed (`delivery_status='sending'`) before sending, so concurrent runs can't double-send
- pg_cron jobs: `itso-email-dispatch` (every 5 min → Edge Function; backup/retry path), `itso-daily` (01:00 UTC → SER/defect reminders + 10-year auto-archive)
- Edge Function secrets: `CRON_SECRET`, `GMAIL_USER` + `GMAIL_APP_PASSWORD` (current provider — Gmail SMTP port 465), `RESEND_API_KEY` (fallback; needs a verified domain to email anyone but the signup address), optional `EMAIL_TEST_RECIPIENT` (redirects all mail), `EMAIL_FROM`, `SITE_URL`
- Local-only secret: `supabase/cron_secret.local.txt` (gitignored)
